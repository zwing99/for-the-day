# Semantic chapters and the initial CSB adapter

The ordered semantic tree owns every text segment once. Verse identities point to text-node fragments in source order, keeping printed labels separate from provider and organizational IDs. `validateSemanticChapter` validates wire structure, node uniqueness, fragment membership/order, provider identity, attribution links, tracking metadata, and intro references. It rejects inconsistent data rather than repairing Scripture. `completeVerseUnits` joins identities sharing fragments transitively, retains ancestor paths, and returns references rather than copied text. Titles and headings remain in the tree independently of verse extraction.

The initial CSB adapter uses `https://v2.api.bible/bibles/{edition}/chapters/{book}.{chapter}` with structured JSON, titles, verse labels/spans, and no notes or chapter numbers. Credentials are sent only in the server request header. The selected generation follows the current [V3 FUMS example](https://docs.api.bible/resources/fair-use/); the [chapter guide](https://docs.api.bible/guides/chapters/) still shows legacy v1 responses. There is no automatic legacy fallback. Authenticated endpoint and edition access must be verified in task 3.3.

Normalization follows the [nested JSON contract](https://docs.api.bible/resources/content-output-formats/): paragraph and inline containers retain source paths/styles, text retains exact characters, supplied verse/organizational identities remain distinct, and printed marker text becomes a verse marker rather than a Scripture leaf. USX title/heading styles remain title/heading groups; q1–q4 become ordered lines with indentation. No stanza breaks are invented from verse numbers. Unknown tag structures retain their children under an unknown group; unsupported wire shapes fail explicitly. Inline nd/it/bd styles propagate marks while preserving text. `meta.fumsToken` is mandatory and the supplied metadata survives intact for later display reporting. The adapter never evaluates provider metadata as code.

Provider failures use typed safe codes, omit upstream bodies/URLs/keys, preserve request cancellation, and expose bounded numeric Retry-After guidance for HTTP 429. Mock tests cover request options, exact text, split/merged and partial identities, unknown structures, title/poetry semantics, token retention, configuration, cancellation, and safe failures. Ordinary tests make no live requests.

## Verified CSB fidelity gate

On 2026-09-26, authenticated v2 requests succeeded for CSB Psalms 23, 3, and 119 and Proverbs 7. Saved responses remain ignored under `.local/provider-samples/`. The local verifier compared every source text segment in order, container hierarchy, attributes, printed markers, exact attribution, and FUMS metadata. Provider verse counts matched 6, 8, 176, and 27 respectively. No Scripture or credentials were copied into tracked fixtures.

Observed structures include nested verse-span wrappers, q1 and unnumbered q continuation lines, d superscriptions, s1/s2 headings, empty b stanza separators, and nd/sup/qs/qac/tl inline styles. These now have invented-text regression coverage. Unnumbered q uses zero indentation; q1–q4 retain their numeric indentation. Verse spans retain membership and become inline groups. Superscripts, italic title/poetic markers, and acrostic marks survive normalization. No material architecture correction was needed.

Run `direnv exec . mise run inspect:csb` only for an intentional live-provider review. `mise run verify:csb-samples` checks existing ignored responses without network requests. Rendered fidelity and cached FUMS reporting remain later verification gates.
