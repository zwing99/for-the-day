# URLs and reader navigation

Routes are `/`, `/:day`, `/:day/psalm/:chapter`, and `/:day/proverbs/:chapter`, with optional `/intro` or a provider's printed verse label. Shared canonical links include `?translation=CSB` (or NIV/NLT/ESV/WEBU), with repeated `org` identity parameters when supplied. Partial and range labels remain strings. Invalid syntax, outside-plan chapters and absent fetched verse labels produce recovery rather than clamping.

Root chooses today's device-local calendar day. A root or installed-app launch follows today: it resumes passage and logical location on the same calendar date, and starts the first passage from its beginning when the date changes. A repeated day number in a later month starts fresh. Returning from the background also advances a day-following session after a local date change; continuously visible reading does not jump at midnight. Today re-enters day-following mode using the local date at the time it is pressed. Explicit links and manual day choices remain on their chosen passage until Today or a new root/app launch. Every day from 1 through 31 remains selectable in every month.

Day-only manual routes may restore that day's active-passage hint. Explicit URL locations override saved passage locations; date-scoped saved locations override intro/first-verse defaults in day-following mode. Versioned guarded storage holds only logical URLs, calendar keys, and preferences, with session-memory fallback. Date-scoped progress is bounded to 90 calendar dates. Older undated locations remain available for manual navigation, without seeding a fresh date's automatic start. No Scripture objects are persisted.

Explicit passage/navigation actions push history. Vertical reading replaces the current entry. Begin replaces an intro entry. Popstate restores while marker observers are suppressed, including within a mounted passage; obsolete fetches are cancelled and late responses ignored. Pagehide and hidden-document events flush the current logical location. Translation adapters and exact cross-translation mapping remain later tasks.

Each navigation has an activation ID. The coordinator accepts settled-marker writes only after that activation's restoration completes, and rejects callbacks from a departing activation immediately. Layout changes during restoration retain its pending readiness notification; popstate uses the current translation preference for links without an explicit translation.

Native scrolling is primary, with `pan-y pinch-zoom` retained. Touch observation never prevents native vertical movement or pinch zoom. Horizontal navigation requires 56px travel, 1.75× horizontal dominance, completion within 700ms, and no established vertical intent. Cancellation, multiple touches, controls and active text selection reject passage changes. Ends are bounded. A horizontal drag reveals an inert adjacent panel; release commits once or returns to the active passage. Reduced motion skips animated settling. Native zoom, selection, window blur, resizing, and opening the menu cancel pending gestures.

The reader menu provides previous/next passage buttons and direct ordered selection; the passage indicators also select directly. All use the navigation coordinator and preserve independent saved locations. ArrowLeft/ArrowRight change passages only from the reading surface. ArrowUp/ArrowDown and PageUp/PageDown move between complete aligned pages. Form controls, settings, active selection, and modified keys retain browser behavior. Passage ends disable their corresponding menu button. Previous/next page controls use the same aligned-page actions as vertical keys.

Fast-scroll correction (2026-09-26): alignment repair selects the page nearest the current scroll position, rather than restricting candidates to a page from the gesture's original position. This avoids rewinding after momentum or rapid input advances farther. Native mandatory snapping and stop-always remain responsible for page stops; repair only aligns the current position. Wheel/touch regression tests and a Chromium scroll-end check cover progress beyond the gesture origin without backward repair.

Prominent button rows have been removed. The reader menu supplies card/passage alternatives and presentation controls; small named indicators allow direct selection. See [reading-first-interface.md](reading-first-interface.md) for the current interaction and browser review.

Adjacent chapter preparation uses the same cache-aware source as foreground reading. After the current passage becomes usable, it warms only the next and previous available passages, one at a time, and reprioritizes after commitment. Foreground navigation joins a matching request or cancels unrelated background work. Day and translation changes cancel obsolete preparation without clearing reusable chapters. A rate limit pauses warming for its supplied delay (60 seconds when absent); access and configuration errors stop warming for that scope. The source owns request sharing, IndexedDB admission, freshness, and eviction. A failed or evicted neighbor loads normally when opened.

Page selection is a passive step: explicit URL reference, compatible saved reference, then introduction or first verse. It resolves packed and merged verse identities against the current chapter. `ReadingSurface` can fit and align that page in passive mode without focus, scroll observation, or location callbacks. Reader activation is the separate commitment step that enables progress, history, focus, and display reporting.

When the adjacent chapter and its fitted saved page are ready, horizontal dragging reveals that exact page in an inert panel. A labeled loading panel remains while content or alignment is unavailable. Commitment reuses ready preview data with a fresh activation and keeps the preview visible until the active surface finishes measured packing, fitting, and saved-page restoration. A cold destination loads and restores its saved page directly. Failed committed loads retain the normal retry control.
